The physical layer does not change

A Meshtastic node is an ordinary LoRa transceiver: same chirp, same SF, BW and CR. It only fixes two parameters that are free in a custom link: sync word 0x2B (RadioLib defaults to 0x12) and a 16-symbol preamble (the default is 8).

In a plain LoRa link, point to point or broadcast, the application puts its bytes in the payload and that is it. Anyone listening with the same settings receives them as they are: no addresses, no repeaters, no encryption. Every custom protocol has to invent all of that.

Meshtastic defines that structure and standardises it for every node: a 16-byte cleartext header plus an encrypted protobuf message. That is why a minimal modem like MeshAT can talk to the network without the official firmware.

What each field solves

Every header field answers a specific problem that shows up in a mesh and does not exist in a direct link.

to / from

Who is talking and to whom. FFFFFFFF is broadcast. The 32-bit NodeNum identifies each node.

id

Random packet number. Together with from it forms a unique fingerprint: when three repeaters forward the same packet, each node processes it only once.

hop_limit

Every repeater decrements it. At 0 the packet stops propagating; without it the mesh would flood forever.

hop_start

How many hops it started with. The difference with hop_limit tells how many repeaters it went through.

channel hash

XOR of the channel name and the key. Lets a node drop packets from other channels instantly, without spending an AES operation.

next_hop / relay

Last byte of the next hop and of whoever rebroadcast it. Used by the routing of recent firmware versions.

encryption

AES-128-CTR. With the public key of the default channel it is not real privacy, but the whole network can read it.

portnum

Multiplexes applications over the same channel: text (1), position (3), node names (4), telemetry (67).

A direct link versus a mesh

With plain LoRa only the nodes within range of the sender receive. In Meshtastic every receiver rebroadcasts while hop_limit remains, and duplicates are dropped by from + id.

The purple node transmits. N3, with the dashed ring, is your node: try sending with and without “Your node repeats”. Each line joins two nodes within radio range.

What joining the mesh adds

In Meshtastic, hops are made by the receiver. A node that only originates and receives (MeshAT v1 and Mesh_Modem_Web v2) depends on others to repeat its messages and adds no range for anyone. When it also repeats (Mesh_Modem_Web v3), it becomes a link of the network: placed in the right spot, like N3 in the simulation, it joins two areas that cannot hear each other.

Rebroadcasting does not require decryption. The raw packet is retransmitted, changing only three header fields. Private channels and other people's direct messages are repeated as well, still encrypted.

Repeating as soon as a packet is heard would make all neighbours transmit at once and collide. That is why each node waits for a contention window that depends on the SNR it received with. Nodes that heard it weakly, usually the farthest ones, wait less and repeat first, because they add the most range. A client that hears someone else repeat cancels its own rebroadcast. A router always repeats, and before the clients.

AT+RELAY=0 / CLIENT_MUTE

Mute

Receives and originates, but never repeats. Adds no range. Useful in a very dense area or to save battery.

AT+RELAY=1 / CLIENT

Client

Repeats after its window and cancels if someone else repeated first. The normal mode: it contributes without duplicating traffic.

AT+RELAY=2 / ROUTER

Router

Always repeats, with priority, and never cancels. Only for a node placed high, with a good antenna and fixed power.

What you gain

Coverage: your node carries messages to areas the others cannot reach.

Redundancy: if a repeater goes down, there is another path.

Implicit ACK: the original sender hears your rebroadcast and knows its message left its area.

Autonomy: a network built only with these modems also has hops.

What it costs

Airtime: every rebroadcast occupies the channel. A router adds all the mesh traffic.

Collisions: more transmitters mean more collisions. The contention window and the cancellation exist for that.

Energy: transmitting is what consumes the most. On a battery board, the mode matters.

Encryption without sending an IV

AES-CTR needs a unique initial counter for every packet. Meshtastic does not send it: it builds it from data that already travels in clear in the header. The receiver rebuilds it the same way and applies the same operation, because in CTR encrypting and decrypting are the same XOR.
